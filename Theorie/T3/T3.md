# Theorie Continious Integration

## 1) Was ist Continuous Integration (CI) und wie wird es umgesetzt?

#### 1. Welche Bedeutung hat Continuous Integration im Softwareentwicklungsprozess?

Continious Integration ermöglicht, die Entwicklerteams zu vergrössern, sowie mehr Bereitstellungen abzuschliessen. Mit der CI können mehrere Entwickler parallel und unabhängig an verschiedene Features arbeiten, ohne einen hohen Aufwand auf die Diskussionen zu setzen. Die features können am Schluss einfach und unabhängig gemerged werden.

#### 2. Welche technischen Prozesse und Werkzeuge ermöglichen eine erfolgreiche Implementierung von CI?
 Ein Versionskontrolsystem (VSC), wie zum Beispiel Git, ist die Grundlage von CI. Es wird auch eine Hosting-Plattform wie z.B. GitHub oder BitBucket gebraucht. Automatisierte Tests sind grundsätzlich die beste Lösung um die Integration zu prüfen. CI's werden bei Pull Requests, sowie beim Code-Review ausgelöst. Es ist auch sinnvoll, die Geschwindigkeit vom Vorgang zu messen.

#### 3. Welche Rolle spielt CI in der Automatisierung und Zusammenarbeit in Teams?

- Automatisierung:

Sobald neuer Code im Repository gepusht wird, laufen Builds und Tests automatisch ab. So wird es erkannt, ob der Code fehlerfrei ist. Das spart Zeit und Kosten in der Qualitätssicherung. Dank den schnellem Durchlauf kann ein neuer Code schnell getestet werden.

- Zusammenarbeit:

Der Entwickler kann unabhängig an seinem Task arbeiten. Am schluss wird der Code problemlos zusammengeführt. Durch Pull Requests und Code Reviews schauen sich die Entwickler den Code an und tauschen sich aus. Die Entwicklung ist somit auch einfacher weiterzuleiten und mehrere Arbeiter können gleichzeitig arbeiten.


## 2) Was sind die Vor- und Nachteile von CI?

#### 1. Welche Vorteile bringt die Einführung von CI für die Softwareentwicklung?

Die Skalierbarkeit ist mit CI für das Unternehmen vergrössert. Die abhängigkeit auf konstante Kommunikation sinkt enorm, da jeder an seine eigene Tasks arbeiten kann. Die Ressourcen werden gespart, da automatisierte Tests vor Regressionen schützen. Die Änderungen werden somit schneller gepusht und können besser reviewed werden. 

#### 2. Welche Herausforderungen können bei der Implementierung und im Betrieb von CI auftreten?

Die Einführung und das Aufsetzen sind die grösste Herausforderung für das Team. Das grösste Problem sind Projekte, die ohne CI gestarted wurden. Alle Testfälle müssen geschrieben werden, was bei grossen Projekten einen Aufwand verursachen. Die Geschwindigkeit ist auch entscheidend im Betrieb, da die TEstfälle immer angepasst werden müssen.

#### 3. Wie beeinflusst CI langfristig die Produktqualität und den Workflow in einem Team?

Produktqualität:

Jede Änderung wird automatisch getested. Somit können die Fehler frühzeitig erkannt und Regressionen verhindert werden. Die Qualität, sowie die Testabdeckung des Projektes wachst.

Workflow im Team:

Die Arbeiter können mehr mergen und parallel zusammenarbeiten. Der Koordinationsaufwand sinkt und das Team kann wachsen. Pull Requests fördern den Wissensaustausch weiter, da es mehr Pull Requests gibt.

## 3) Was ist Continuous Testing, und wie wird es umgesetzt?

#### 1. Wie unterscheidet sich Continuous Testing von traditionellen Testmethoden?

Bei dem Traditionellen Testing wird meistens am Ende der Entwicklung getestet, ausser wenn die Arbeiter mit dem TDD (Test-Driven-development) vorgehen. Punkt liegt beim Erkennen von Fehler.

Beim kontinuierlichen Testing wird mit jeder Änderung automatisch getestet. Die Arbeiter erhalten schnelles Feedback und die Fehler werden schneller erkannt. Punkt liegt beim Vermeiden von Fehler.

| | Traditionell | Continuous Testing |
|---|---|---|
| **Zeitpunkt** | Am Ende der Entwicklung | Laufend, bei jeder Änderung |
| **Durchführung** | Meist manuell | Weitgehend automatisiert |
| **Feedback** | Langsam | Schnell |
| **Fehlerkosten** | Hoch, da spät entdeckt | Niedrig, da früh entdeckt |
| **Verantwortung** | Separates QA-Team | Gesamtes Team |
